usage: traceql.py exemplars [-h] [--q Q] [--since SINCE] [--end END] [--k K] [--quantile QUANTILE]
                            [--baseline-range BASELINE_RANGE] [--limit LIMIT] [--max-lines MAX_LINES] [--json]

traceql.py exemplars [--q '<조건식>'] [--since 1h] [--k 3] [--quantile 0.95] [--baseline-range 7d] [--limit 100]

서버 span 을 오류 · 느림 · 정상 셋으로 나눠 묶음마다 대표 트레이스 k 개 — 트레이스를 열지 않는다.
느림의 임계는 엔드포인트(서비스, 서버 span 이름)마다: 평소 p95(조사 창 직전 --baseline-range 의 spanmetrics) → 조사 창 p95 →
표본 p95 순으로 있는 것. 건마다 적용한 임계와 그 출처(baseline · window · sample)가 붙는다. metrics 1 회 + traces 검색 1 회.
요약 줄은 표본 수 · 임계 초과 수 · 평소 기대 비율((1 − 분위수) × 100%). 검색이 --limit 을 넘으면 절단 표시.

원본(span 트리 · 검색 응답)은 호출 디렉터리의 raw.json 에 남고 stdout 은 환원물이다. 창은 summary.txt 머리에
남는다. stdout 은 --max-lines 에서 잘린다. --json 은 경로만.

options:
  -h, --help            show this help message and exit
  --q Q                 TraceQL 조건식(중괄호 없이). 비우면 서버 span 전부
  --since SINCE         창 길이. 기본 1h
  --end END             창 끝 (now · -10m · unix초 · RFC3339). 기본 now
  --k K                 묶음별 상위 k. 기본 3
  --quantile QUANTILE   분위수 (0, 1). 기본 0.95
  --baseline-range BASELINE_RANGE
                        평소 분포의 구간 — 조사 창 바로 앞. 기본 7d
  --limit LIMIT         검색 트레이스 상한. 기본 100
  --max-lines MAX_LINES
                        stdout 줄 수 상한. 기본 40 — 나머지는 호출 디렉터리의 summary.txt 에
  --json                stdout 에 요약을 찍지 않고 호출 디렉터리 경로만(파일은 항상 남는다)
