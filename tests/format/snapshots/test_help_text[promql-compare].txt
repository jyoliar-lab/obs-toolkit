usage: promql.py compare [-h] [--since SINCE] [--end END] [--max-lines MAX_LINES] [--json] [--baseline BASELINE]
                         [--step STEP]
                         query

promql.py compare '<PromQL>' --since 1h [--end <시각>] [--baseline 1d] [--step 60s]

같은 식의 p95 를 지금 창과 `offset <기준선>` 에서 한 질의로 받아 시계열별 차이만:
`×비율  Δ절대  now p95  base p95  {레이블}` — 비율 내림차순, 그 뒤에 기준선 0 · 기준선 없음 · 지금 없음.
--baseline: 1d(기본 — 1일 전 같은 시각, 주기성 있는 지표용) · 1w(1주 전) · prev(직전 창 — 급변 감지용).
기준선 창에 시계열이 없으면(보존 밖 · 그때 없던 pod) "기준선 없음" — 0 으로 나누지 않는다.

계산은 백엔드가 한다 — 코어는 질의를 조립해 결과만 받는다(연산당 질의 1회). 창(compare 는 기준선도)은 호출 디렉터리의
summary.txt 머리에 남는다. stdout 은 요약이고 --max-lines 에서 잘린다. --json 은 경로만.
실패해도(HTTP 오류 · 전송 실패 · 예산 초과) 호출 디렉터리가 남는다 — tmp/obs/<시각>-<명령>-failed/ 에 보낸 호출 전부(실패 포함)와 오류 문구, 오류 메시지 끝이 그 경로다.

positional arguments:
  query                 PromQL

options:
  -h, --help            show this help message and exit
  --since SINCE         창 길이. 기본 1h
  --end END             창 끝 (now · -10m · unix초 · RFC3339). 기본 now
  --max-lines MAX_LINES
                        stdout 줄 수 상한. 기본 40 — 나머지는 호출 디렉터리의 summary.txt 에
  --json                stdout 에 요약을 찍지 않고 호출 디렉터리 경로만(파일은 성공 · 실패 모두 남는다)
  --baseline BASELINE   기준선 창 — 같은 식의 offset: 1d(기본 — 1일 전 같은 시각) · 1w · prev(직전 창)
  --step STEP           서브쿼리 해상도(두 창에 같다). 기본 창 길이/60 (최소 15s)
