# Python — 타입을 가급적 명시한다

Python 코드를 작성·수정할 때는 **type hint를 가급적 명시한다.**

- 함수·메서드의 **매개변수와 반환 타입**을 적는다. 반환이 없으면 `-> None`도 적는다.
- 타입이 자명하지 않은 **모듈·클래스 수준 변수**에도 어노테이션을 단다.
- 기존 코드를 수정할 때 시그니처를 건드리면, 그 시그니처에 힌트를 함께 채운다. 다만 **힌트 추가만을 위한 무관 파일 수정은 하지 않는다** — 티켓 범위가 우선이다.
- 대상 저장소에 mypy·pyright 등 타입 검사가 걸려 있으면 그 설정이 우선이다 — 이 규칙은 검사가 없을 때의 기본값이다.

## 구조화된 값 — dict 대신 dataclass

어떤 값(필드 구성)이 사용될지 명확하다면, **dict나 임의 object 대신 `dataclass`를 가급적 사용한다.**

- 키가 고정된 dict, `types.SimpleNamespace`, 필드만 담는 맨손 클래스가 후보다 — 필드가 정해져 있으면 dataclass로.
- 키가 런타임에 정해지는 진짜 매핑(설정 병합, 카운터 등)은 dict가 맞다 — 억지로 바꾸지 않는다.
- 외부 경계(JSON 파싱·API 응답)는 받는 즉시 dataclass로 옮기고, 내부에서는 그 타입으로 다룬다.
- 기존 코드베이스가 이미 다른 관례(pydantic, attrs, NamedTuple)를 쓰면 그 관례를 따른다.
